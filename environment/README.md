# Isolated host environment

`host-lock.yaml` records immutable Kitsu/Zou source refs and the official combined Docker test image. The image is disposable and local-only; Docker uses anonymous container-owned PostgreSQL and preview volumes. No Production data or external Google Drive credentials are attached. Passing this host does not establish VFX Studio Production compatibility.

The pinned host runs Kitsu `v1.0.70` and Zou `v1.0.94` (source commits are in `host-lock.yaml`), with Python 3.10.12. A read-only official Git tag check on 2026-10-12 found the same latest Kitsu and Zou tags. No official Kitsu/Zou pair compatibility guarantee was found. Production versions remain unknown.

The official Zou plugin page is mounted at `/plugins/vfx_files/*`, proxied through Kitsu's same-origin `/api` route. The Files feature gate defaults off. Plugin-owned additive migrations `vxf_0001` through `vxf_0006` create `plugin_vfx_files_*` tables. Routes use host cookies and an identity-bound CSRF proof; cookie-only and cross-origin mutations fail.

Pinned-host verification on 2026-10-12 passed 92 pytest tests against the real Zou/PostgreSQL host, installed branch plugin and separate worker process. The installed-page Playwright flow passed with synthetic Manager, Artist A, Artist B and Supervisor identities: template discovery/activation and Task folder provisioning; Artist A uploaded w001; Artist B downloaded exact bytes and uploaded w002; the page showed both after refresh; Artist B published w002; the worker persisted a FakeStorage artifact, manifest, QC and native Zou OutputFile; unauthorized approval returned 403; the Supervisor approved the exact Publish; and Artist A accepted the Handoff after refresh.

Publish recovery killed the separate worker after FakeStorage had durably accepted the reserved artifact but before the database artifact checkpoint. After lease expiry, a second worker completed against the same provider ID. A second injection killed the worker after Zou created an OutputFile but before the plugin recorded its ID; lease retry moved the Publish to `native_create_ambiguous`, and the native OutputFile count remained unchanged. The one-shot permit blocked an automatic second create. Replay after completion is idle, stale lease generations cannot complete, and late older Publish completion does not move Latest Published backwards. Any manual native-create retry still requires audited authoritative absence proof.

A fresh disposable PostgreSQL database with representative Working File and Publish rows exercised vxf_0006 downgrade and re-upgrade. Downgrade removes `source_revision_file_id` and `publish_folder_id`; re-upgrade recreates empty nullable columns. A snapshot taken before downgrade restored both values. Therefore vxf_0006 downgrade is a destructive rollback and must not be used against a Production database; use a consistent snapshot restore. A separate full application-level backup/restore rehearsal is recorded in `docs/environment/backup-restore-acceptance-2026-10-12.md`.

Frontend verification passed 12 Vitest tests, 3 fixture Playwright tests (2 pinned-host-only tests skipped in the fixture run), the separate installed-page Playwright E2E, and the Vite production build. Gitleaks found no secrets in the Git history or changed product files; its broad directory scan reported four generic-pattern matches only in the ignored pinned Zou source snapshot under `.superpowers`.

The separate full application-level backup/restore rehearsal passed; encrypted offsite backup custody and Production recovery remain unverified.
