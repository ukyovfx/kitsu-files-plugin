# VFX Kitsu Files Findings-to-Design-to-Test Traceability

**Design:** `docs/superpowers/specs/2026-10-11-vfx-kitsu-files-plugin-design.md`
**Implementation plan:** `docs/superpowers/plans/2026-10-11-vfx-kitsu-files-plugin.md`
**Status (2026-10-12):** The isolated branch now includes the installed-page Publish, QC, Approval and Handoff controls. The installed page passed the complete synthetic browser workflow against pinned Kitsu 1.0.70 / Zou 1.0.94, with real plugin API/PostgreSQL, separate worker and persistent FakeStorage. A pinned-host crash test also interrupted execution after Zou created an OutputFile but before the plugin recorded its ID; lease retry fenced the one-shot permit into reconciliation without creating a duplicate. A vxf_0006 scratch-database rehearsal confirmed downgrade/re-upgrade loses `source_revision_file_id` and `publish_folder_id`; a pre-downgrade database snapshot restored both. A separate full application snapshot was restored into another pinned disposable host; the installed page verified Working downloads and pointers, a pre-validation Worker was refused, and a manifest-matched one-shot Worker returned idle. Google Drive has injected-transport contract coverage but no live Drive acceptance. Production compatibility remains blocked pending sanitized read-only host inventory.

## Independent review record

One read-only reviewer pass found a High race in native OutputFile creation: a lease successor could repeat a slow in-flight non-idempotent call. The corrected design now persists a one-shot create permit before calling Zou, disables automatic retries, and blocks ambiguous outcomes for audited reconciliation; Task 4 now has a lost-lease slow-create test. The reviewer also supplied Google’s explicit pre-generated folder ID guarantee; the spec now cites it and retains only the My Drive/Shared Drive auth/capability acceptance gate. No reviewer edits were made.
